# TH5：テストハーネス安全性の5項目（チェックリスト）

自作のテストランナー／ハーネスを実装・変更するときに確認する。実際に発生したフォークボム事故（テストがランナー自身をサブプロセス起動し、ランナーがそのテストを再発見して無限再帰した）の再発防止として作成した。

| 番号 | 項目 | 内容 |
| --- | --- | --- |
| TH1 | 自己再帰ガード | ハーネス／ランナー自身をサブプロセスとして起動するテストがある場合、子プロセスにのみ環境変数を渡し、子側で検知したら即座に `skip` する。ガードなしで「自分の本体を呼び出す」テストを書かない |
| TH2 | 探索カバレッジの回帰テスト | 探索対象の glob／パターンを変更したら、既存の全テストディレクトリ（配置規約が異なるものを含む）を漏れなく拾えることを保証するテストを併せて書く |
| TH3 | 初回実行時の保険 | 新しいハーネスやその変更を最初に動かすときは、`ulimit -u <上限>` でプロセス数上限、`timeout <秒>` で強制終了時間を設定してから実行する。保険なしでいきなり全体実行しない |
| TH4 | サブプロセスe2eの最小化 | 「ランナーの動作をランナー自身で検証する」テストは、可能な限り内部関数の直接呼び出し（サブプロセスなし）に置き換える。サブプロセス経由が必要な場合も、実リポジトリの `test/` ではなく `tempfile` 上の最小フィクスチャに対して実行する |
| TH5 | CI側の二重化 | CI実行コマンド自体にも `timeout` を付け、暴走時にジョブが早期に落ちるようにする |
